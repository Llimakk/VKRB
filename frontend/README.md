# VKRB Navigator — Web-редактор

Веб-редактор для администраторов: рисовать полигоны помещений, расставлять навигационные узлы, соединять их рёбрами, привязывать комнаты к узлам.

Стек: **React 19 + TypeScript + Zustand + Webpack 5**. Без CSS-фреймворков — все стили inline.

Базовый запуск (через Docker) — в [корневом README](../README.md). Здесь — как разрабатывать редактор и как им пользоваться.

## Запуск дев-сервера

Удобно для горячей перезагрузки при правке UI:

```bash
cd frontend
npm install
npm run dev
```

Откроется на `http://localhost:3000`, проксируя API-запросы на `http://localhost:8000` (см. `webpack.config.js`).

Параллельно нужен поднятый backend:

```bash
docker compose up -d db minio api
```

## Production-сборка

Финальная сборка кладётся в `frontend/dist/`, откуда её отдаёт nginx-контейнер:

```bash
npm run build
```

Nginx подхватит свежие файлы автоматически — перезапускать ничего не нужно.

## Режимы редактора

Переключение — в левой панели или потенциально хоткеями (пока без них).

| Режим      | Что делает                                                                       |
| ---------- | -------------------------------------------------------------------------------- |
| **Create** | Клик — поставить узел (тип выбирается отдельно: room/toilet/stairs/...)          |
| **Edit**   | Drag узлов, drag вершин полигонов, drag waypoints на рёбрах, клик по ребру — добавить waypoint, Shift+click по waypoint — удалить |
| **Connect**| Клик-клик: добавить ребро (или удалить, если уже есть)                            |
| **Polygon**| Клик-клик-клик — рисовать контур. Близко к первой точке — замкнуть.              |
| **Measure**| Линейка: померять расстояние в метрах                                            |
| **Delete** | Клик по узлу/ребру/полигону — удалить                                            |
| **Bind**   | Сначала клик по полигону, потом по узлу-комнате — узел становится точкой входа в объект |

### Pan / Zoom

- **Alt + drag** — пан канваса.
- **Ctrl/Cmd + wheel** — зум к курсору.
- Кнопки `−`/`100%`/`+` снизу справа — зум кнопками, клик по проценту — сброс вида.

## Сохранение

Кнопка **Сохранить** в header пушит весь граф плана через `PUT /admin/plans/{id}/graph`. Бэкенд делает полную замену nav-узлов и рёбер этого плана, а также обновляет полигоны объектов. Объекты, которых нет в payload, удаляются — это намеренно, чтобы убирать «осиротевшие» помещения без полигона.

## Валидация плана

Иконка **Проверка** в header открывает панель с предупреждениями:

- полигон без точки входа
- полигон ссылается на удалённый узел
- узел не подключён ни к одному ребру
- exit без GPS-координат
- дубли имён (исключение: одноимённые входы одной аудитории)

Клик по проблеме центрирует канвас на узле.

## Полезные мелочи

- **Авто-цепь** в create-режиме коридора: новый коридорный узел автоматически соединяется с предыдущим.
- **Связь с некоридором**: каждый новый коридорный узел соединяется с ближайшим не-коридором (комнатой, лестницей и т.п.).
- **Waypoints**: чтобы ребро шло вокруг препятствий внутри сложной комнаты, в edit-mode кликни по линии связи — добавится точка изгиба. Тащи её мышкой, Shift+click — удалить.
- **Координаты как в Яндексе**: в NodeEditPanel для exit-узла можно вставить `55.770885, 37.690803` в поле широты — оба поля заполнятся.
- **Undo/redo** — `Ctrl+Z` / `Ctrl+Shift+Z` (через `saveHistory()` в сторе).

## Конвенции кода

- **Только inline-стили** (React `style={{ ... }}`). Tailwind/CSS-modules не подключены и не нужны.
- **Палитра** — в `constants.ts`: `#2563EB` accent, `#F3F4F6` bg, `#111827` text, `#6B7280` muted, `#E5E7EB` border.
- **Состояние** — в Zustand-сторе. Никакого `useState` для бизнес-данных в компонентах.
- **История** — `saveHistory()` вызывается в каждом мутирующем экшене стора; `undo()`/`redo()` восстанавливают снапшот.
